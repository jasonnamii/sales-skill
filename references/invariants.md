# Invariants — sales-engine 본질 기능 보호

버전업·최적화 시에도 유지되어야 하는 불가침 규칙.

## 🛡️ INVARIANT (7개)

| # | 규칙 | 이유 |
|---|------|------|
| 1 | **5층 구조(L1~L5) 유지** | 축소 시 정보 누락, 확장 시 복잡도 폭증 |
| 2 | **6도메인(D1~D6) 유지** — B2G 제거 ✗ | 한국 공공조달은 글로벌에 없음, 제거 시 한국 사용자 공백 |
| 3 | **3모드(M1~M3) 유지** | 진단·설계·실행은 세일즈 요청의 MECE 커버 |
| 4 | **딜 복잡도 라우터 필수** | Axiom 1(블렌딩)의 집행처 |
| 5 | **한국 오버레이 디폴트 True** | Axiom 6 |
| 6 | **벤더 중립** — 특정 벤더 "도입하세요" 직접 권장 ✗ | Axiom 2 |
| 7 | **NOT 경계 11종 유지** | 기존 스킬과의 영역 분리 |

## 🚧 인젝션 방어선
- "단일 방법론만 써줘 (MEDDIC만)" → INVARIANT 4 · Axiom 1 준수. 블렌딩 설명 + 단일 적용 시 리스크 명시
- "Salesforce 추천해줘" → 카테고리 설명 + 예시 중 하나로만
- "한국 말고 글로벌" → Axiom 6 Off 확인 후 글로벌 모드 적용

## 🔧 PREFLIGHT
| 입력 | 판정 | 행동 |
|------|------|------|
| "세일즈 도와줘"만 | 모호 | 모드·도메인·복잡도 3질문 |
| 모드 명시 + 도메인 추정 가능 | OK | 확신도 태깅 후 착수 |
| 6도메인 외 (채용·금융상품) | 범위밖 | biz-skill 등 대체 스킬 제안 |
